## Temuan yang perlu ditangani

### Tinggi

1. **Keanggotaan shortlist dapat ditambahkan tanpa kode undangan.** Kebijakan insert `shortlist_members` hanya menguji `user_id = auth.uid()` (`supabase/migrations/0001_init.sql:287-288`). Pengguna login yang memperoleh UUID shortlist dapat menambah dirinya langsung, lalu membaca shortlist dan propertinya melalui kebijakan member (`:280-293`). Edge Function `shortlist-invite` memeriksa kode undangan, tetapi RLS memungkinkan jalur langsung melewatinya. Hapus izin insert klien dan jadikan fungsi yang memvalidasi kode sebagai satu-satunya jalur bergabung. Perlu migrasi database terapan, bukan hanya perubahan file.

2. **Sinkronisasi tiga fitur inti gagal untuk data baru.** Store membuat ID `ss_<timestamp>`, `kpr_<timestamp>`, dan `sl_<timestamp>` (`src/store/useAppStore.ts:197,208,242`), sedangkan `saved_searches.id`, `kpr_scenarios.id`, dan `shortlists.id` bertipe UUID (`supabase/migrations/0001_init.sql:195-210,245-246`). Insert akan ditolak PostgreSQL. Seluruh penulisan di `src/data/sync.ts:70-147` mengabaikan hasil/error sehingga UI tetap tampak berhasil. Gunakan UUID valid atau biarkan database membuat ID, kemudian tangani error dan tampilkan status sinkronisasi.

3. **Data workspace akun tetap terlihat setelah logout.** Event logout hanya mengubah `syncUserId` menjadi `null` (`src/auth/AuthProvider.tsx:41-49`); `savedIds`, pencarian, KPR, shortlist, dan riwayat tidak dibersihkan (`src/store/useAppStore.ts:149-306`). Pada perangkat bersama, pengguna berikutnya dapat melihat data pengguna sebelumnya sampai hidrasi akun baru selesai; saat request gagal, data lama dapat tetap muncul. Reset state akun secara atomik saat pergantian sesi dan cegah hasil request lama mengisi akun baru.

4. **Data tamu tidak persisten meski UI dan dokumentasi menyebut lokal.** `useAppStore` dibuat dengan `create` biasa tanpa middleware penyimpanan (`src/store/useAppStore.ts:149`), sehingga saved property, pencarian, simulasi, dan shortlist hilang saat proses aplikasi dimulai ulang. Layar sign-in menyebut data tersimpan lokal (`src/app/sign-in.tsx:72`). Tentukan penyimpanan perangkat yang sesuai dan strategi migrasi data tamu ke akun.

### Sedang

5. **Kegagalan backend disamarkan sebagai katalog demo.** Saat Supabase dikonfigurasi, empat fungsi repository masih mengembalikan mock ketika query error (`src/data/repository.ts:80,87,147,154`). Pengguna melihat listing contoh sebagai data produksi dan UI tidak menerima error untuk ditampilkan. Batasi mock hanya pada mode demo yang eksplisit; propagasikan error jaringan/database pada build terhubung.

6. **Notifikasi penurunan harga tidak tersambung penuh.** Preferensi di layar hanya mengubah Zustand (`src/store/useAppStore.ts:236-237`), sedangkan Edge Function hanya mengirim ke user yang mempunyai baris `notification_prefs.price_drops = true` (`supabase/functions/price-drop-alerts/index.ts:52-59`). Tidak ada penulisan preferensi ke tabel itu dari aplikasi. Fungsi juga menginsert event untuk setiap pemrosesan (`:38-44`) tanpa penanda idempotensi, sehingga pemanggilan ulang dapat mengirim duplikat. Fallback scan membandingkan `previous_price` dengan string `'price'` (`:33`), bukan ekspresi perbandingan kolom. Simpan preferensi ke backend dan deduplikasi berdasarkan perubahan harga.

7. **Endpoint notifikasi memakai service role tanpa autentikasi payload dalam handler.** `price-drop-alerts` menerima JSON `record`/`old_record` dari request (`supabase/functions/price-drop-alerts/index.ts:18-27`), kemudian memakai service role untuk membuat event dan mengirim push. Jika endpoint dapat dipanggil klien dengan JWT yang diterima oleh gateway, pemanggil dapat memalsukan penurunan harga. Verifikasi sumber webhook atau gunakan job internal dan cocokkan perubahan dengan database sebelum pengiriman. Status proteksi gateway/deployment belum diuji.

8. **Permintaan penghapusan akun baru tercatat, belum diproses.** UI melakukan upsert `account_deletion_requests` (`src/app/account-deletion.tsx:25-36`), namun repo tidak mempunyai worker/admin flow yang memprosesnya. Klaim selesai dalam 30 hari bergantung proses di luar repo. Kebijakan `for all` pada tabel permintaan (`supabase/migrations/0002_account_deletion.sql:9-10`) juga membolehkan pemilik mengubah `status` sendiri; batasi ke insert/select dan sisakan perubahan status untuk proses admin. Verifikasi proses operasional sebelum mengklaim penghapusan tersedia.

9. **Validasi statis belum hijau.** `npm run typecheck` gagal pada navigasi developer. Lint tidak dapat dijalankan dari checkout bersih karena `eslint`/konfigurasi tidak dideklarasikan. Saat konfigurasi Expo sementara dipasang, lint mendeteksi masalah React Hooks di Home/Search/AuthProvider/Skeleton, ditambah false positive resolver Deno. Tambahkan konfigurasi lint yang mengecualikan atau mengatur Edge Function dan bereskan error aplikasi sebelum rilis.

10. **Cakupan verifikasi otomatis belum ada.** `package.json` tidak mempunyai script test; tidak ada berkas test atau workflow CI yang dilacak. Alur RLS, sinkronisasi ID, pergantian akun, dan notifikasi membutuhkan uji integrasi khusus. Export web yang lulus tidak membuktikan build Android/iOS, auth redirect, MapLibre, atau FCM berjalan.

### Dokumentasi dan rilis

11. `ARCHITECTURE.md` masih memakai `[APP_NAME]`, `react-native-maps`, monorepo/API/Redis/OpenSearch yang belum terwujud di repo. `docs/feature-gaps.md` memuat beberapa baris lama yang bertentangan dengan kode terbaru, termasuk penghapusan akun. Pisahkan arsitektur target dari kondisi implementasi saat ini dan perbarui audit gap.
12. `RELEASE.md` masih menandai situs kebijakan privasi/penghapusan akun dan Play Console sebagai pekerjaan tertunda. `src/app/privacy-policy.tsx:52` sendiri menyebut teks sebagai draf yang perlu tinjauan legal. Kesiapan rilis Play belum bisa disimpulkan dari export web.
